## Обновление 2026-08-12 (ночь): разбор жалобы на "гавнище" в переводе (скриншот усталости)
Пользователь показал скриншот с "Ты  в состоянии крайнего изнурения" (двойной пробел) и
"Ты  почти у твой физического предела" (именительный падеж вместо родительного после «у»).
Это НЕ проблема промпта/Квена — баг в рантайм-движке грамматики (plugin/OstraI18n/Patches.cs,
RuData.cs), нашёл и исправил:

1. **Двойной пробел** (VerbPrefix, Patches.cs): при опущенной связке [is] (`vf.OmitPresent`)
   код добавлял "" вместо формы глагола, но статические пробелы вокруг токена в шаблоне
   ("[us] [is] X" -> "Ты" + " " + "" + " X") давали двойной пробел. Это касалось ВООБЩЕ
   ВСЕХ фраз с опущенной связкой по всей игре, не только тех трёх на скриншоте. Исправлено:
   при form=="" убираем предыдущий пробел из interactionOutput. Коммит 747e205.

2. **КЛЮЧЕВОЕ ГРАММАТИЧЕСКОЕ ОТКРЫТИЕ**: таблица `Pronouns["pos"]` в langs/lang_ru/grammar.json
   хранит только именительный падеж муж. рода ед. числа ("мой"/"твой"/"его"/"её"/"их"/"его",
   индексы I/you/he/she/they/it). НО "его"/"её"/"их" (3-е лицо) в русском — это ЗАСТЫВШИЕ
   формы, которые НЕ СКЛОНЯЮТСЯ вообще ни по падежу, ни по роду, ни по числу
   существительного! ("его дом"/"у его дома"/"его домов" — везде "его"). Значит
   [them-pos]/[3rd-pos] ПОЧТИ ВСЕГДА корректны независимо от контекста (they обычно NPC,
   3-е лицо) — баг реально проявляется ТОЛЬКО у [us-pos] (и гипотетически [my-pos]), когда
   индекс = I/you, потому что "мой"/"твой" — настоящие склоняемые слова. Это сильно сужает
   масштаб проблемы по сравнению с тем, что казалось на первый взгляд.
   Проверено сканом: [us-pos] встречается перед НЕ-муж.-ед.-числа существительным в СОТНЯХ
   записей по всей игре (conditions/interactions/etc) — это системное ограничение (только
   одна несклоняемая форма на "pos"), совпадает с уже задокументированным пунктом
   "притяжательные только мужского рода" в архитектурном аудите. НЕ чинить построчно —
   нужна either (a) таблица pos с формами по родам/числам + передача рода
   существительного в токен (движковая работа), либо (b) переформулировка каждой фразы
   вручную/через Qwen с ограничением "после pos-токена — муж. род, ед. число, именительный
   падеж" (это то, что делает tools/fix_pos_case.py, но только для случая "предлог+pos").

3. Точечно исправлено: 55 записей, где [us-pos]/[them-pos]/[3rd-pos] стояли сразу после
   предлога родительного падежа (у/для/из/от/до/без/около/...) — tools/fix_pos_case.py
   (Qwen-ассистированная переформулировка, сохраняющая набор токенов). Плюс вручную
   исправлены 6 записей, где ИМЕННО [us-pos] (не them-pos!) стоял перед не-муж.-ед.
   существительным: ChronicMangledHand2, DcAging03, DcAging05, DcFatigue04, StatEsteem,
   SOCTradeFixerConvoStartBusy — переформулированы так, чтобы после токена шло муж. ед.
   существительное в им. падеже (например "запас сил" вместо "физические силы").

Живая проверка: 168 литералов/68 методов, 24861 поле, 0 сирот, 0 исключений, 0 ошибок
валидатора. tools/fix_pos_case.py — переиспользуемый инструмент для будущих подобных правок
